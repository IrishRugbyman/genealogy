# CLAUDE.md - frontend/

React 19 + Vite SPA served at `genealogy.lbzgiu.xyz`. Read `../CLAUDE.md` first for the
commune/locality model, which shapes half the routes.

## Commands

```bash
npm install
npm run dev          # port 5173, proxies /api -> localhost:8005
npm run build        # -> dist/, which nginx serves directly (no reload needed)
npm run type-check   # tsc -b
```

There is no test runner and no ESLint config here: `type-check` plus the API suite is the
whole safety net. Keep it passing.

## Structure

```
src/
  lib/api.ts     # every API call + its TanStack Query hook (useSearch, usePerson, …)
  lib/utils.ts   # formatDate, sexLabel, personName, cn
  lib/timeline.ts
  routes/        # file-based routing, see below
  components/    # chart/ map/ person/ place/ search/ tree/ ui/
```

**Nothing family-specific is hardcoded.** The Sosa root's name and the branch labels come
from `GET /api/tree` (`useTree`, `useBranchLabels`); the depot's contact name from
`VITE_DEPOT_CONTACT` in the gitignored `.env.local`. This repo is public.

`lib/api.ts` is the only place that talks to the network - add the fetch and its hook there,
not in a component. `components/ui/` holds the primitives (Badge, Card, EmptyState,
PageHeader, Skeleton, StatCard…); compose those rather than restyling ad hoc.

## Family access and the living

The API masks people who may be alive unless this browser signed in (see
`../api/CLAUDE.md`, "The living"). A masked record carries `living: true` (or
`spouse_living`, `father_living`...) and the name "Personne vivante". `useFamilyAccess()` in
`lib/api.ts` signs in or out and **resets the whole query cache**, because every cached
answer was shaped for the previous viewer; signing in also unlocks `/depot` when its
password is the same, and unlocking `/depot` signs in. UI: `components/ui/FamilyAccess.tsx`
(header button + dialog, and the inline form on a hidden person's page). The timeline skips
unions and births of hidden relatives rather than listing them undated.

## Names

The source marks an unknown part of a name with a placeholder (`n`, `N`, `?`, `x`).
`fetchJson` in `lib/api.ts` renders them once for every response (`tidyNames`, using
`displayName` in `lib/utils.ts`): "n MOREAU" becomes "? MOREAU", as GeneWeb shows it,
and a name with no known part becomes "Inconnu". Components never see the raw placeholder.

## Text size

The type scale is one step above Tailwind's (`--text-xs` 13px, `--text-sm` 15px, in
`index.css`). The "Aa" button (`TextSizeToggle`, `lib/textSize.ts`) sets
`html[data-text-size]` to 112.5% or 125%, stamped before first paint by `index.html`; since
everything is in rem it scales text, spacing and controls together. Two consequences:
never size text in `px` (use rem), and the tree, laid out in SVG pixels, scales its node box
with `nodeSize(useTextScale())`. Media queries do not see the root size, so the header does
not use a breakpoint for its nav: `useNavFits` in `__root.tsx` measures an invisible copy
and switches to the drawer when the full nav does not fit.

`public/robots.txt` and the `noindex` meta keep the site out of search engines.

## Navigation

`components/ui/SiteNav.tsx`. The bar holds the four pages that carry almost every visit:
Recherche, Arbre (opens the Sosa root's tree; absent when no root is configured), Carte,
Dépôt. Every other page sits under "Explorer", each with a one-line hint, because "Bans"
or "Qualité" alone tells a family reader nothing. A new page goes in `EXPLORE_ITEMS`, not
in the bar. The drawer lists the same two groups.

## Routing

TanStack Router, file-based. **`src/routeTree.gen.ts` is generated by the Vite plugin - never
edit it by hand**; add a file under `src/routes/` and let it regenerate.

| Route | Page |
|---|---|
| `index.tsx` | search: debounced input, filters, infinite scroll |
| `people.$id.tsx` | person detail: Famille (parents, then each union with its children), timeline (vertical by default on a phone), siblings, lineage |
| `families.tsx` / `.index.tsx` / `.$id.tsx` | families browse + detail |
| `places.$id.tsx` | locality page (own events + commune + sibling localities) |
| `communes.$insee.tsx` | commune page (events aggregated across all its localities) |
| `map.tsx` | choropleth map with granularity selector |
| `tree.$id.tsx` | interactive hourglass tree (d3-hierarchy + SVG) |
| `relation.$id1.$id2.tsx` | relationship path between two people, via common ancestor |
| `stats.tsx` / `gaps.tsx` | statistics dashboard / data-coverage gaps |
| `professions.*` / `distinctions.*` / `military-ranks.*` | catalog browse + detail |
| `bans.tsx` | BAN localities reference |
| `depot.tsx` | uploads; `?person=I…` turns it into a correction form for that person |

The locality/commune split mirrors the database: `/places/$id` is one village or hamlet,
`/communes/$insee` aggregates every locality of that commune.

## Map rendering model

The basemap is CARTO raster (`light_all` / `dark_all`) with `VITE_CARTO_KEY` appended
(`cartoTiles` in `GenealogyMap.tsx`). Since late August 2026 the keyless endpoint returns
every tile as a valid PNG reading "API KEY REQUIRED", HTTP 200: nothing errors, so a defaced
map is the only symptom. CARTO is also retiring raster; the freight app has already moved to
its vector style (`~/quant/freight/frontend/src/lib/basemap.ts`) and this map would follow
the same path the day raster stops answering.

`components/map/GenealogyMap.tsx` runs three independent layer types, toggled by the active
granularity mode. Getting this wrong makes events silently vanish from the map, so:

1. **French choropleth** (GeoJSON polygons), one layer per mode
   (country/region/department/commune); only the active one is visible. French commune-level
   places carry `lat=NULL/lon=NULL` and render as polygon fill. The commune layer is built
   from `commune_insee` - hamlets roll up into their commune via `get_fr_commune_counts` -
   fetching polygons by INSEE code. Each feature carries `insee` plus a representative
   `place_id`, used by the popup's "Voir les personnes" link and by the search fly-to.

2. **Non-French marker clusters**: three `L.MarkerClusterGroup` instances
   (region/department/commune - *not* country, already covered by the GeoJSON). Membership
   comes from `placeGranularity()`: `locality` set -> commune; `locality` null and `county`
   set -> department; both null and `state` set -> region. Only the cluster matching the
   active mode is shown. Country mode shows polygons only.

3. **French hamlet markers** (`hamletLayerRef`): small points for geocoded French localities
   with `kind` in (`hameau`/`former-commune`/`lieu-dit`), drawn on top of the choropleth in
   commune mode only. These are the deliberate exception to "French places have `lat=NULL`"
   (populated by the ETL's hamlet geocoder); the chef-lieu stays NULL and renders via its
   polygon.

The region and department choropleths key off `places.county`/`places.state`, which the ETL
keeps in sync with COG. Legacy region names (Lorraine, PACA) do not match the modern GeoJSON
polygons - if events disappear from a region, suspect stale admin columns and rerun the
ETL's admin sync (`sync_place_admin.py --apply`) before touching the map code.
